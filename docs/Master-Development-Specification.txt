Master Development Specification
Reusable Local Business Directory Platform
Project type: Multi-industry local business directory platform
Primary framework: Next.js
Initial vertical: Roofing contractors
Core principle: Build the directory engine once, then reuse it for different industries, cities, states, brands, and domains without rewriting the application.
1. Project Vision
The platform will be a modern local-business discovery system combining:
- Searchable local business listings
- Video-first business profiles
- Google ratings/review content
- Business photo galleries
- Interactive map/list search
- Rich business profiles
- Sponsored and Featured listings
- Stripe-powered advertising subscriptions
- Custom CMS
- Excel/CSV importing
- Google Sheets/Google Drive synchronization
- Local SEO landing pages
- Built-in blog
- Portable deployment/install system
The system must not contain hard-coded roofing-specific logic.
Roofing will simply be the first configured industry.
Future examples:
Roofers
Plumbers
HVAC Contractors
Electricians
Dentists
Attorneys
Real Estate Agents
Restaurants
Auto Repair
Home Improvement Contractors

62. Core Prisma Concept
A simplified foundation:
model Industry {
  id          String     @id @default(cuid())
  name        String
  slug        String     @unique
  description String?
  active      Boolean    @default(true)

  businesses  Business[]
  categories  Category[]

  createdAt   DateTime   @default(now())
  updatedAt   DateTime   @updatedAt
}

model Business {
  id                String   @id @default(cuid())

  externalId        String?
  industryId        String
  industry          Industry @relation(fields: [industryId], references: [id])

  name              String
  slug              String

  description       String?

  phone             String?
  email             String?
  websiteUrl        String?

  googlePlaceId     String?
  googleRating      Float?
  googleReviewCount Int?

  address1          String?
  address2          String?
  city              String?
  state             String?
  postalCode        String?
  country           String @default("US")

  latitude          Float?
  longitude         Float?

  verified          Boolean @default(false)
  featured          Boolean @default(false)
  sponsored         Boolean @default(false)
  homepageFeatured  Boolean @default(false)
  published         Boolean @default(false)

  customFields      Json?

  media             BusinessMedia[]
  reviews           GoogleReview[]
  promotions        BusinessPromotion[]

  createdAt         DateTime @default(now())
  updatedAt         DateTime @updatedAt

  @@unique([industryId, slug])
  @@index([externalId])
  @@index([googlePlaceId])
  @@index([city, state])
}

93. Final Product Philosophy
The system should ultimately work like this:
INSTALL SOFTWARE
      ↓
NAME DIRECTORY
      ↓
CHOOSE INDUSTRY
      ↓
BRAND DIRECTORY
      ↓
CONNECT GOOGLE
      ↓
CONNECT STRIPE
      ↓
IMPORT BUSINESSES
      ↓
PUBLISH
Then for another vertical:
NEW INSTALLATION

"Central Florida Plumbing Directory"

Import plumbers.

Launch.
No redevelopment.
No new CMS.
No new database architecture.
No rebuilding business profiles.
The industry, categories, branding, listings, pricing, content, and configuration change — the software does not.
Recommended first build milestone
The first milestone should be an MVP roofing directory containing the complete underlying multi-industry architecture but only enough functionality to prove the entire workflow:
CMS → create/import business → enrich listing → show search result → map → business profile → Featured/Sponsored toggle → publish.
Once that complete vertical slice works correctly, we expand into Google Drive automation, Stripe subscriptions, blogging, SEO automation, and the portable installer.
That approach gives us something functional early without sacrificing the larger platform architecture.
